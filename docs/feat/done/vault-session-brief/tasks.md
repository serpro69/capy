## Reflection

The reader, renderer and both surfaces followed the plan closely. Most of the effort went into consequences the plan did not name. Exact-ID-first lookup (ADR-038) became necessary once full IDs from search hits were fed back as prefixes, and it touched every captured-ID path. Closed-pipe exit behavior needed three review rounds to pin down, because Cobra parses flags, validates arguments and runs pre-run hooks before RunE. Search eligibility and the brief header used different ID budgets. The single-snapshot read was simple to build but hard to prove. It needed a test seam placed after resolution: a seam placed later let rename and reassignment pass even when the snapshot was broken. Timing assumptions did not carry across machines. On x86-64 Linux, sqlite3mc key derivation takes about half of a ~300 ms brief, so deadline tests must anchor on measured resolution, not on a fraction of the run. Future vault work should expect any new captured-ID consumer to need an exact lookup path.
