## SQLite checks

- Using the repository's three FTS5 table definitions and a temporary parent table, a synthetic sidecar-free replacement matched zero parent rows. Following the current child-write order committed one row for that UUID in each of `vault_fts`, `vault_chunks` and `vault_chunks_trigram`. SQLite's query plan for an absent-UUID delete reported a virtual-table scan in all three.
- With two connections to a temporary WAL database, one connection read the empty marker set. The other atomically deleted X and inserted its marker. The first connection's next live-row query returned nothing under separate reads. Under a single read transaction it returned X from the earlier snapshot. The next transaction saw X's marker in both cases.

These checks exercise the relevant SQL behavior. The encrypted Go store, CLI, and sweep regression cases are implementation work tracked in [tasks.md](./tasks.md).

## Implementation readiness check

A subsequent read of all four documents at `1da0346` identified these interactions between the earlier fixes and the existing code.

- **Existing orphan rows.** A live-parent-only cleanup would preserve text left by the old replacement race when the first marker arrived for an absent UUID. A SQLite fixture using the repository's FTS definitions confirmed that targeted first-time cleanup removes that text from all three tables and preserves a neighboring session. Repeating the marker and adding a second project pair for the same absent UUID issued zero FTS deletes.
- **Merge reporting under concurrency and failure.** The current replacement planner separately queries destination metadata, and the batch reporter queries it again after commit. Either lookup can race a delete. Cancellation can also break the merge loop and return success, while the CLI returns early on a merge error. The revised plan binds reporting to the observed or committed transaction and preserves partial counts on failure. [Merge reads and writes](../../../../internal/vault/merge.go#L148) · [CLI error path](../../../../cmd/capy/vault.go#L1013)
- **Reader activation and task order.** The previous Task 1 raised the public reader maximum while the merge implementation still read only live sessions. The revised sequence pairs version 4 with working propagation and enables default local recording with its warning and opt-out.
