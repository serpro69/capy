# Implementation plan for vault session deletion

The storage and command behavior is specified in the [design](./design.md). Implement against temporary encrypted vaults using synthetic keys.

## Local deletion and archive writes

**Schema.** Share the deletion table definition between the fresh schema in `internal/vault/store.go` and migration `0008_session_deletions` in `migrations.go`. Define `readerVersionSessionDeletions = 4` in `codec.go`. Verify schema parity, version preservation on an empty migration, and atomic first-marker stamping. Enable the public maximum with merge support. [Columns and composite key](./design.md#compatibility)

**Deletion transaction.** Resolve the full UUID. Local recording captures the live row's effective project, and a missing local target keeps its existing missing-session outcome. A received deletion retains the selected source pairs, including when the live row is absent.

Before inserting pairs, identify distinct UUIDs that are live or being remembered for the first time. Reuse the parameterized `WHERE session_uuid IN (...)` cleanup from `RebuildFTSBatch`, once per FTS table per nonempty batch of those UUIDs. Delete live parents and let sidecars and metadata cascade in the same transaction. An independently archived child keeps its own row.

**Disk import.** In `internal/vault/import.go`, check every candidate UUID immediately after platform and project selection. This precedes `os.ReadFile`, decompression, sidecar reads, duplicate handling, digest lookup and size admission. Actual and dry runs report `excluded / deleted` for a marked candidate, even if its file cannot be opened. Propagate lookup errors. The guarantee begins with a discovered `SessionFile`. Discovery may already have read metadata to select the candidate.

**Full writes.** In `writeRecord`, check the marker inside the immediate write transaction. Check both the error and count from the parent's replacement `RowsAffected()` before touching files, indexes or overrides. A marked UUID yields `excluded / deleted`. A zero-row replacement with no marker yields `skipped / session disappeared`. Stop processing that record in either case. Return committed outcomes per input through `WriteBatch`, `writeOne` and their individual retries. Real SQL errors still roll back the transaction.

**Index and location writes.** Return per-UUID outcomes from the transaction behind `RebuildFTSBatch` and retain the aggregate survivor count used by `Reindex`. Map each `ftsPending` input and retry to its own outcome. At `UpdateLocationHint`, distinguish a marked UUID from an unmarked missing parent for import while preserving the standalone caller's missing-row error. A moved rollout that also needs a rebuild gets one final outcome. A delete committed before the rebuild takes precedence over the earlier hint update. Propagate lookup, update and commit errors.

## Cross-machine merge and reporting

**Source reads.** After `OpenSourceForMerge` finishes its existing open/checkpoint, begin one source read transaction for preview or apply. Use that transaction for the reader-version gate, schema probes, marker and live UUID enumeration, and reads of session content, sidecars, names and projects. Adapt the existing query helpers to accept the query methods they use. Close each result set before issuing the next query on that transaction. Release the snapshot on success, cancellation and failure. Keep destination transactions bounded and separate. Exercise the source race by committing a remembered delete from another connection between marker enumeration and live enumeration. This merge sees the complete pre-delete source record, and the next sees its marker. A source already deleted when the snapshot starts contributes the marker immediately.

**Destination writes.** Apply selected source markers first. Group pairs by UUID, use the existing source-project substring matcher, and preserve pairs verbatim even if the live destination has a different label. Ignore transcript admission filters for markers. For incoming live UUIDs, check destination deletion state before loading the source payload. Read the destination marker, digest and any metadata needed for a replacement preview from a consistent view. Today `SessionDigest` and the later `sessionMetadata` lookup can disagree simply because a delete committed between them.

Classify live writes and metadata-only reconciliation inside their destination transaction. A marked UUID gives `excluded / deleted`. An update planned for a parent that disappeared without a marker gives `skipped / session disappeared`, including a same-hash record carrying only a title or project change. Return each successful write's status and reportable winning metadata from the transaction and publish them after commit. A later delete must not convert that successful write to a readback error. Preserve driver and commit errors.

**Accounting.** Track distinct live UUIDs removed, new selected pairs recorded, and selected pairs already present as separate counts. Print a full UUID for each deletion-related outcome. Marker-only entries lack a platform and do not enter live-session platform subtotals. In `printImportResult` display marker-only results even when there are no live session entries. For preview, group and deduplicate selected pairs and read destination membership and existing pairs consistently per group. Apply computes the same units inside its write transaction and publishes them after commit. Cleaning orphan FTS rows adds zero to the live-archive removal count.

**Partial completion.** If a marker batch fails or cancellation interrupts the merge, release the source snapshot and return the partial result with the error. Keep earlier committed counts. Identify rolled-back work as failed or unprocessed and exclude it from success counts. In `newVaultMergeCmd`, print any partial results before returning the error. Preserve the normal nonzero exit for recorded per-session failures. Test a failure after a committed batch, then retry. The earlier pairs should be reported as already present, and only the outstanding work should add counts.

**Examples to verify.** Select two new pairs for one live UUID, and include a different UUID sharing its first eight characters. Compare preview, actual and repeat counts and full-ID output. Use a third vault to check that an empty receiver forwards a deletion. Separately, have A delete X under `personal` and B receive that deletion while holding X under `work`. A `work`-filtered merge from B leaves C's X alone unless B holds a separately originated matching pair. A full or `personal` merge propagates it. Keep a different UUID from the same project as a control.

## Local configuration

Add the presence-aware boolean `vault.remember_deletions` to `internal/config` with a default of true. Resolve it once using the invocation project, including `--project-dir`, before displaying the delete preview. Use that value for the confirmed operation. Its stderr preview identifies the full UUID and explains permanence, re-import and cross-vault effects for the selected mode. Show it with `--yes` as well as before the interactive prompt. Declining preserves the session and creates no marker. Test both previews, explicit false at each applicable configuration layer, re-import after a one-time delete, and continued suppression of an existing marker after a config change.

Force the stale-replacement interleaving in both import and merge using a sidecar-free session with search text and no metadata overrides. Plan its replacement, commit an opted-out delete, then flush. Assert the skip outcome, zero live rows, and zero rows for that UUID in each of `vault_fts`, `vault_chunks`, and `vault_chunks_trigram`. Confirm that a fresh ordinary import can subsequently admit the complete session.

## Operator documentation and verification

Set `supportedReaderVersion` to 4 together with full merge handling and update the merge help that currently promises a non-destructive union. In `internal/vault/platform_test.go`, pin the deletion milestone at 4 and keep the platform milestone at 3. Update the future-format open and source-merge fixtures in `codec_test.go` and `merge_test.go` to reject version 5, including the error text. Verify reopen after receiving the first marker in an empty destination, monotonicity across later writes, and importing live data from a version-3 source. A source requiring version 4 with its deletion table missing is inconsistent. Reject it before applying any destination deletions. A compatible legacy source without that table contributes zero markers.

Expose default local recording and its opt-out together with the permanence notice. Ship these changes as one release with updated reader invariants in `AGENTS.md` and `docs/architecture.md` and operator guidance in the README and `docs/reference/vault.md`.

Use temporary encrypted vaults with both synthetic keys, `-tags fts5`, and the race detector for affected suites. Run `make bench-quality` when changing the shared index deletion path per repository policy. Document the retained identifiers, local opt-out, absence of undelete, source-project matching, preview units, and the upgrade/restart procedure.
