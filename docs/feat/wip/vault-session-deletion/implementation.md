# Implementation plan for vault session deletion

The storage and command behavior is specified in the [design](./design.md). Implement against temporary encrypted vaults using synthetic keys.

## Local deletion and archive writes

1. Share the `vault_session_deletions` table definition between the fresh schema in `internal/vault/store.go` and migration `0008_session_deletions` in `migrations.go`. Use the [columns and composite key in the design](./design.md#compatibility). In `codec.go` make `readerVersionSessionDeletions = 4` the supported maximum. Stamp it on first marker insertion, whether local or received. Verify fresh and migrated schemas, version preservation on an empty migration, rollback of the first marker and its stamp together, and monotonicity across later ordinary writes.
2. For an explicit remembered delete, resolve the row by exact UUID and capture its current effective project inside the write transaction. For a received delete, retain only the selected source pairs. In both cases look up live destination membership by primary key **before** index cleanup. Share the bounded, parameterized `WHERE session_uuid IN (...)` deletion from `RebuildFTSBatch` for the three index tables. Run it once per table per nonempty batch of distinct live UUIDs. Delete those parents and let their sidecars and metadata cascade in the same transaction as the new pairs. An absent local delete keeps the existing missing-session outcome. An incoming marker for an absent UUID still commits and forwards. Preserve the children of an addressed parent.
3. In `internal/vault/import.go`, immediately after platform and project selection, check the candidate UUID for a marker on every sighting. This check precedes `os.ReadFile`, decompression, sidecar reads, duplicate handling, digest lookup and size admission. Both real and dry runs report `StatusExcluded` with reason `deleted`. A membership-query error is an error for that candidate. This guarantee starts at the import boundary with a discovered `SessionFile`; discovery may already have read platform metadata for selection. Verify both modes against an unopenable marked candidate and a readable live neighbor, and check the startup sweep's excluded count.
4. Return per-record outcomes from the store to the importer and merger. In `writeRecord`, check the marker inside the immediate write transaction. Independently check the error and count from the parent's replacement `RowsAffected()` before touching files, FTS, chunks, or overrides. A zero-row replacement with no marker yields `StatusSkipped` / `session disappeared`; a marker yields `StatusExcluded` / `deleted`. Neither path writes children, stamps a reader version for unwritten content, nor retries the record as a new insert. Report committed outcomes by input position or UUID through `WriteBatch`, `writeOne`, individual retries and merge's post-write reporting. Genuine SQL failures retain the existing rollback/error handling.
5. Cover the writes that bypass `writeRecord`. Return the per-UUID rebuild result from the transaction behind `RebuildFTSBatch`; keep the aggregate survivor count available to `Reindex`. Map each `ftsPending` input, including a single-record retry, to updated, excluded/deleted, or skipped/disappeared. At the `UpdateLocationHint` transaction boundary distinguish a remembered deletion from an unmarked missing row for the import caller, preserving the standalone missing-row error for existing callers. For a moved rollout whose index also needs rebuilding, report one final outcome for that candidate. A deletion committed before the rebuild takes precedence over the earlier hint update. Carry genuine lookup, update and commit errors through.

## Local configuration

Add the presence-aware boolean `vault.remember_deletions` to `internal/config` with a default of true. Resolve it in the invocation project's configuration for the delete command in `cmd/capy/vault.go`. Its stderr preview identifies the full UUID and explains permanence, re-import and cross-vault effects for the selected mode. Show it with `--yes` as well as before the interactive prompt. A declined confirmation writes nothing. Test both previews, explicit false at each applicable configuration layer, re-import after a one-time delete, and continued suppression of an existing marker after a config change.

Force the stale-replacement interleaving in both import and merge using a sidecar-free session with search text and no metadata overrides. Plan its replacement, commit an opted-out delete, then flush. Assert the skip outcome, zero live rows, and zero rows for that UUID in each of `vault_fts`, `vault_chunks`, and `vault_chunks_trigram`. Confirm that a fresh ordinary import can subsequently admit the complete session.

## Cross-machine merge and reporting

**Source reads.** After `OpenSourceForMerge` finishes its existing open/checkpoint, begin one source read transaction for preview or apply. Use that transaction for the reader-version gate, schema probes, marker and live UUID enumeration, and reads of session content, sidecars, names and projects. Adapt the existing query helpers to accept the query methods they use. Close each result set before issuing the next query on that transaction. Release the snapshot on success, cancellation and failure. Keep destination transactions bounded and separate. Exercise the source race by committing a remembered delete from another connection between marker enumeration and live enumeration. This merge sees the complete pre-delete source record, and the next sees its marker. A source already deleted when the snapshot starts contributes the marker immediately.

**Destination writes.** Apply selected source markers first. Group pairs by UUID, use the existing source-project substring matcher, and preserve pairs verbatim even if the live destination has a different label. Ignore transcript admission filters for markers. Enforce the UUID guard for incoming live rows before reading their payload and inside write transactions, including same-hash/smaller or excluded rows that reconcile metadata. A concurrent remembered deletion takes the excluded/deleted path. Use committed outcomes for reports so a later metadata lookup on an intentionally excluded or vanished row cannot turn a correct outcome into an error.

**Accounting.** Track distinct live UUIDs removed, new selected pairs recorded, and selected pairs already present as separate counts. Print a full UUID for each deletion-related outcome. Marker-only entries lack a platform and do not enter live-session platform subtotals. In `printImportResult` display marker-only results even when there are no live session entries. For preview, group and deduplicate selected pairs and read destination membership and existing pairs consistently per group. Apply computes the same units inside its write transaction and publishes them after commit. A rollback contributes no successful removal or addition. Repeated merges of absent UUIDs perform zero FTS deletes, even against a populated destination. Verify that structurally with a statement counter at the cleanup boundary, independent of elapsed time.

**Examples to verify.** Select two new pairs for one live UUID, and include a different UUID sharing its first eight characters. Compare preview, actual and repeat counts and full-ID output. Use a third vault to check that an empty receiver forwards a deletion. Separately, have A delete X under `personal` and B receive that deletion while holding X under `work`. A `work`-filtered merge from B leaves C's X alone unless B holds a separately originated matching pair. A full or `personal` merge propagates it. Keep a different UUID from the same project as a control.

## Operator documentation and verification

With the code change, update the hard-coded reader maximum in `AGENTS.md` and `docs/architecture.md`, and revise the merge/delete help, README and `docs/reference/vault.md`. In `internal/vault/platform_test.go`, pin the deletion milestone at 4 and keep the platform milestone at 3. Update the future-format open and source-merge fixtures in `codec_test.go` and `merge_test.go` to reject the first version above the new maximum (5), including the error text. Verify that receiving the first marker in an empty destination stamps 4, a version-3 source still merges, and a legacy source cannot revive a marked UUID.

Use temporary encrypted vaults with both synthetic keys, `-tags fts5`, and the race detector for affected suites. Run `make bench-quality` when changing the shared index deletion path per repository policy. Document the retained identifiers, local opt-out, absence of undelete, source-project matching, preview units, and the upgrade/restart procedure.
