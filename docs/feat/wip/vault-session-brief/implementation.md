# Implement an archived session brief

## Terminal brief

Register `brief <session-id>` under `newVaultCmd` in `cmd/capy/vault.go`. Use the vault group's key and path selection, exactly one positional argument and the existing literal-prefix rules. Reject interactive mode. The terminal and MCP call the same vault reader and renderer. The command can run with only the vault credential. [Vault CLI](../../../../cmd/capy/vault.go#L32) · [Prefix helper](../../../../internal/vault/store.go#L24)

### Open an existing vault

Give the reader a dedicated, short-lived connection on both surfaces, including when the server already has a writer. Use the `VaultStore`'s selected path and `RequireVaultKey`. Establish the earlier of the caller deadline and two seconds before opening. Classify a missing path separately from a permission or I/O error. Open with `sqliteutil.EncryptedDSN`, `mode=ro`, a short busy timeout (50 ms) and `sqliteutil.OpenWithCanary`. The SQLite open flags must themselves preclude creating the main database if it disappears after a path check. Close this SQL handle directly after finishing the read transaction. Keep the normal writer's migration, corruption recovery and checkpoint lifecycle with its owner. [Canary and error classification](../../../../internal/sqliteutil/sqliteutil.go#L225) · [Normal vault open](../../../../internal/vault/store.go#L475)

Use ordinary SQLite WAL locking so a reader sees committed frames while another connection is active. SQLite may use auxiliary WAL/SHM files for that coordination. An `immutable=1` open could miss committed frames. The brief neither creates an absent database nor changes archived data, runs migrations, repairs a damaged file or checkpoints a writer. A separately running startup sweep retains its existing behavior.

In one read transaction, check the vault's reader-version marker with `checkReaderVersion`, validate the required vault tables and columns, then use that snapshot for every data query. Honor an absent marker row in a recognized vault. Require the per-message FTS columns, session platform and index version, and name/project override tables. Use the migration ledger and schema shape to recognize a supported predecessor missing a required migration. Direct its operator to open that vault with the current CLI's ordinary migrating path. A ledger claiming a missing structure is current indicates an inconsistent layout. Report an unsupported newer reader version explicitly. A compatible schema can contain sessions with an older **index version**. Serve those indexed rows and use the selected session's version for the reindex hint. [Reader marker](../../../../internal/vault/codec.go#L168) · [Vault migrations](../../../../internal/vault/migrations.go#L26) · [Index versions](../../../adr/025-vault-index-version-and-reindex.md)

### Select the exchange

1. Use `sessionIDPrefixPattern` and `projectScopePredicate` with bound arguments and the existing session/project join aliases. Select at most two scoped session rowids. Return a scoped miss or “ambiguous, use a longer ID” at this point. A second row establishes ambiguity even when ten share the prefix. For a unique row, join the name and project overrides using the existing effective-value precedence. Keep the exact UUID in SQL for the FTS predicate, for example with a scalar subquery on the selected session rowid. SQL can match even a legacy filename-derived ID too large to display. [Project lookup](../../../../internal/vault/session_project.go#L48) · [Metadata-only precedent](../../../../internal/vault/store.go#L1370)
2. Scan the matching `vault_fts` **positions** once. Filter by exact session UUID, `subagent_id = ''` and roles `user` and `assistant`. Order by numeric turn, message and line positions, then rowid. Fold the ordered rows with constant Go state. Remember the first user row. Each new user row becomes the latest request and clears its previous assistant candidate. Keep the last subsequent assistant in that user's turn. Ignore assistant-only turns, tool and system rows. Deduplicate the opening/latest user by rowid. [Scanner ordering and roles](../../../../internal/vault/scanner.go#L241)
3. Fetch text for at most three winning rowids in that transaction. Query or iteration failure, cancellation, or failure to finish the read discards the result. `GetSession` loads raw JSONL for every prefix candidate and is unsuitable here. The brief reads neither the main blob nor sidecars. A fresh invocation resolves the prefix and scope again and can observe a replacement under the same UUID. [Import replacement](../../../../internal/vault/import.go#L371) · [Merge replacement](../../../../internal/vault/merge.go#L279)

## Render the brief

Use a single UTF-8 text renderer for both surfaces. Make every untrusted field a single quoted value with escapes for embedded quotes, newlines, control and formatting characters. Reserve the response framing, citations, omission/status text and one final newline first. Limit the finished ID to 128 bytes, title to 256 and effective project to 512. Validate the stored platform against the known tokens and surface an unrecognized value as an incompatible archive entry. Use fixed placeholders for an absent imported title or project. A displayed ID that required clipping, redaction or substitution is explicitly a preview. Diagnostics and navigation may use only an intact, safely encoded identity.

Bound the reader as well as the output. Read at most 64 KiB of **complete input per displayed field** into Go. In SQL, use `length(CAST(value AS BLOB))` and a guarded projection to return either the complete value or an omitted flag for a larger value. This counts bytes past an embedded NUL and avoids transferring an oversized field to Go. Use the database's full identity for joins and scope checks. A larger field is omitted whole with a reason. For fields within this bound, normalize invalid UTF-8, apply `sanitize.StripSecrets` to the full value, escape for display, then clip on complete rune/escape boundaries. Keep quotes balanced and the omission marker inside the field allowance. This also covers legacy text and transcript-supplied project paths. Do not pass a pre-clipped secret fragment to the sanitizer. [Imported path fallback](../../../../internal/vault/import.go#L665) · [Sanitizer](../../../../internal/sanitize/sanitize.go#L52)

From the remaining excerpt allowance, give a distinct opening entry up to one fifth, capped at 512 finished bytes. Divide the rest between the latest user and assistant. Give unused space from a short, omitted or absent entry to the other latest entry. Show a single shared opening/latest entry when applicable. An omitted body keeps its role and message-start citation. Use the same bounds for empty-index, pending-assistant and stale-index statuses. Write the final CLI bytes once, propagate write errors and count the MCP text after protocol decoding.

## MCP brief

Register the read-only tool and handler in `internal/server`. Validate the argument names and types before vault access. Require a literal session string of at least eight bytes. Reject embedded NUL in either text selector before passing it to the SQLite LIKE helpers. Match the same session validation in CLI. Validate a supplied `project` as a string and use `vaultProjectScope` for widening, including the existing boolean/string handling of `all_projects`. An absent or empty selector defaults to the server's imported-path scope. If default scope was requested but the server has no project directory, fail before lookup. Use `getVault()` for opt-in and path ownership only. A disabled vault yields its own diagnostic. The reader opens its dedicated connection and never calls the lazy writer's `getDB`. Track a validated call's final reply once via `trackToolResponse`, including an availability or query error. Validation errors follow the existing untracked vault handler convention. This ID lookup has no keyword-search admission or footer. [Tool registration](../../../../internal/server/tools.go#L15) · [Scope helper](../../../../internal/server/tool_vault_search.go#L122)

Use the common vault-hit formatter for the dedicated and federated keyword paths. Identify the source transcript and label its zero-based chunk start, including for title-only and split hits. An eligible main hit gets a short instruction to request the **latest exchange** with its displayed full session ID and the **same** `project`/`all_projects` arguments as the search (leave them omitted for default scope). For example, a full main hit can say `Latest exchange: call capy_vault_brief with this session ID and the same project/all_projects arguments.` A fixed instruction avoids interpolating a long or sensitive selector. Offer it only if the entire usable ID survives safe display. Show sidecar identity on sidecar hits and offer the action on a standalone child's own main hits. Legacy session-labelled knowledge hits carry knowledge attribution only. Apply the same display protection to newly presented hit metadata. If compact replies ship, charge the action to its first full hit's 3,072-byte allowance and let references point there. Both features can ship independently. [Shared formatter](../../../../internal/server/tool_vault_search.go#L143) · [Compact writer](../compact-search-replies/implementation.md#bound-the-complete-reply)

## Verification

Start task 1 by measuring the selected access path. Use an encrypted fixture with 1,000 sessions across projects, 100 indexed rows per session and 256 bytes of text per row (25,600,000 indexed text bytes). Keep the oldest target at 100 rows. Record the DB/WAL sizes and query plan. Measure the live WAL case, the first open after writer close and three subsequent fresh readers. Identify OS cache conditions. Each positive workload case must return the expected complete brief within two seconds, including open, selection, rendering and close. A timed-out lookup fails this check. Check a shorter caller deadline during scanning with no successful partial output. If the target fails reproducibly, resolve the query cost before wiring both surfaces. The [review recheck](review-design-2026-11-23.md#resolution-after-recheck) records the storage-path prototype and its limits.

Use both platform fixtures, same-row deduplication, tool-only assistant, pending reply, no user and a stale index. Interleave a committed replacement or delete between reader statements to verify one snapshot, then call again to see the new state. Exercise cold absent, valid empty, wrong key/damage, older schema and newer reader marker. Verify a live WAL-only commit is visible. Check the public CLI exit/streams and MCP success/error flags, display bounds, both search follow-ups and stdio registration. Document the installed tool set, including the routing generator and its committed output.
