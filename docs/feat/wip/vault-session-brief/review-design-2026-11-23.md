## P0 — Critical

### 1. The proposed query can quote future text at an earlier cutoff · TECH_RISK

In capy's Claude fixture, physical line 1 says “Let me look.”, line 2 adds a tool call, and line 3 adds “Done.” All three are persisted as one assistant row at line 1. In the Codex fixture, the assistant text is on line 7 and a tool call on line 9 is attached to that same row. Filtering by line, role and turn before sorting still returns the completed row. A read transaction and a deterministic tie-break cannot recover the earlier contents. The proposed check against a later **turn** would pass in both cases. **Confidence 10/10.** Both decoder fixtures passed, and with a CLI built from this checkout I imported a synthetic Claude transcript and searched for a word first introduced on line 2. The public search cited line 1. [Historical promise](design.md#interface) · [Planned query and check](implementation.md#terminal-brief) · [Claude input](../../../../internal/vault/golden_test.go#L472) and [indexed row](../../../../internal/vault/testdata/golden/snapshots.scan.json#L15) · [Codex input](../../../../internal/vault/codex_fixtures_test.go#L557) and [expected row](../../../../internal/vault/codex_decoder_test.go#L81)

**Recommendation.** Deliver the latest indexed exchange first. If the physical-line promise is essential to the first release, specify how to retain or reconstruct each quoted part's origin, how old indexes behave and how reindex, replacement, merge and deletion maintain that evidence. Put a cutoff *inside* both example rows and check the actual text returned by CLI and MCP. Merely recording the final contributing line would let the reader suppress a whole row but would also lose the valid earlier reply.

## P1 — High

### 2. A ranked hit can point the brief at the wrong exchange · INCONSISTENT

Both MCP search tools use chunk retrieval. The anchor is the **first** message in a window of up to four turns, or the first message of the entire transcript when it fits in one chunk. Every part of a split window inherits that anchor. In a two-turn encrypted fixture, a word appearing only in the second reply matched at line 3 in per-message search. The ranked chunk showed that word and reported line 0. Following the proposed call would show the opening request with no reply. **Confidence 10/10.** I ran both retrieval paths over the same imported fixture. [Search follow-up](implementation.md#mcp-brief) · [Chunk construction](../../../../internal/vault/chunker.go#L40) · [Result mapping](../../../../internal/vault/chunk_search.go#L148) · [Federated search](../../../../internal/server/tool_search.go#L194)

**Recommendation.** Label a chunk-start link precisely, offer the latest brief for the named archive, or carry a verified message coordinate when offering a brief at the match. Specify the behavior for title-only hits that may have no matching message. Check a match late in a short session and a split window in both MCP tools. Preserve the sidecar ID and omit a main-transcript link for sidecar hits. For users starting in the terminal, the current per-message coordinate is available in `vault search --json`; the plain table omits it. [Search output](../../../../cmd/capy/vault.go#L516)

### 3. Ordinary vault open changes the outcome of an absent or damaged vault · TECH_RISK

The plan requires distinct absent-vault, missing-session, wrong-key and storage-failure results, and describes a read-only tool. The normal lazy open creates the parent directory and database, initializes the schema and applies migrations. On classified corruption it can back up the file and open a replacement. Normal storage-owner close also checkpoints the WAL. An SQL read transaction starts after those decisions. **Confidence 10/10.** On an absent temporary path, the checkout-built `vault list --json` returned `[]` and left a new database. The recovery and close behavior are explicit in the current store. [Interface](design.md#interface) · [Vault open and recovery](../../../../internal/vault/store.go#L475) · [Initialization](../../../../internal/vault/store.go#L513) · [Close](../../../../internal/vault/store.go#L647) · [Lazy MCP handle](../../../../internal/server/server.go#L173)

**Recommendation.** Specify an existing-vault read path for a cold CLI or MCP call. Preserve authenticated opening, the minimum reader-version check and visibility of committed WAL data. Define the result for an older schema that needs migration. Test a cold missing path, an existing empty vault, wrong key and damaged storage, including the files left afterward. A cached healthy MCP handle can serve a snapshot without transferring its checkpoint ownership to the brief. The merge-source opener also checkpoints, so reusing it would need a different close/open contract. [Merge-source open](../../../../internal/sqliteutil/sqliteutil.go#L260)

### 4. The metadata header has a different redaction path from the excerpts · MISSING

The design requires the effective project on every brief. A custom label is redacted when set, but its fallback is the imported project path. A transcript-provided working directory is stored there verbatim. A recognized credential in that path would reach both surfaces even when every selected message was sanitized. Terminal-control escaping and byte clipping do not redact a credential. **Confidence 9/10.** The import, override and fallback paths are explicit. The plan bounds each displayed field but gives no redaction rule for metadata. [Displayed fields](design.md#interface) · [Imported path](../../../../internal/vault/import.go#L665) · [Label normalization](../../../../internal/vault/session_name.go#L59) · [Effective project](../../../../internal/vault/session_project.go#L39)

**Recommendation.** Apply display redaction to metadata before clipping, then escape controls and count final UTF-8 bytes. Keep the original values for selection. Test an imported path containing a synthetic recognized credential across the clipping boundary, a long title, and multiline quoted text resembling a role citation. Verify that the request, reply and their genuine attribution still fit the complete brief.

## P2 — Medium

### 5. A cross-project search needs a follow-up that preserves its selector · INCOMPLETE

A caller can discover an archive outside its current imported path using an explicit project label or `all_projects`. Replaying the example brief call with only the UUID and line silently restores the default scope and misses that same archive. The shared hit formatter receives the result alone. Reconstructing the selector from its displayed project also loses the distinction between an imported path and a custom label. **Confidence 9/10.** Standalone scoped reads are specified, but no acceptance case follows the emitted instruction from a widened search. [MCP task](tasks.md#task-2-request-a-scoped-brief-from-mcp-and-from-search) · [Scope resolution and formatter](../../../../internal/server/tool_vault_search.go#L122) · [Project predicates](../../../../internal/vault/session_project.go#L58)

**Recommendation.** Carry the original selector or give one explicit instruction to reuse it. Exercise search → brief on a relabelled archive outside the current directory, through both dedicated and federated search. Keep guidance within the sibling proposal's search response budget. For an ambiguous prefix, a two-candidate probe establishes “at least two.” Today's CLI ambiguity formatter reports the slice length as an exact total. [Compact reply contract](../../done/compact-search-replies/design.md#what-the-caller-receives) · [Existing ambiguity formatter](../../../../cmd/capy/vault.go#L1876)

### 6. A search citation can change meaning between calls · AMBIGUOUS

One read transaction keeps the parts of a brief consistent. Import and merge can still replace a UUID with a divergent transcript of equal or greater total size **between** the search and the brief. The same line can then belong to a different request. The tasks call for two imports without specifying what a caller using the first citation should observe. **Confidence 9/10.** Replacement is explicit in both writers. Whether a brief should pin the earlier revision is a product choice. [Verification](implementation.md#verification) · [Import replacement](../../../../internal/vault/import.go#L371) · [Merge replacement](../../../../internal/vault/merge.go#L279)

**Recommendation.** The inexpensive contract is to identify each result as a fresh read of the current archive and document that an earlier hit can go stale. If an exact follow-up is promised, bind it to the relevant content and projection revision, recheck those in the snapshot and return a stale result on mismatch. Exercise a divergent replacement that moves the cited text, plus deletion. A metadata-only rename should still display the current title as designed.

### 7. Test the lookup cost before committing to the access path · TECH_RISK

The plan correctly flags the unindexed FTS columns but leaves “realistically populated” and “routine timeout” undefined. I used the table declaration from this checkout in SQLite 3.37.2 and selected one latest eligible user row from the same fixed 100-row session. At 10,000 total rows the query took approximately 151,100 SQLite VM instructions. At 100,000 it took 1,501,200. Both plans scanned the FTS table and used a temporary sort. This measures scaling for one selector in plain in-memory SQLite. Encrypted cold/warm latency and the complete brief remain unmeasured. **Confidence 10/10** in the scan risk. The two-second deadline could still be adequate for the intended vault size. [Performance assumption](design.md#assumptions) · [Planned verification](implementation.md#verification) · [FTS schema](../../../../internal/vault/store.go#L131) · [Earlier full-scan experience](../../../adr/025-vault-index-version-and-reindex.md)

**Recommendation.** Move the feasibility check to the start of task 1. Set the target archive size in total indexed rows and bytes, keep the chosen session fixed, and time the entire encrypted read cold and warm, including cancellation under a shorter caller deadline. Decide up front what result would require a different read path. Bound text materialized in Go as well as bytes emitted to the user. The timing should guide whether an additional index is worth its lifecycle cost.

## Clean areas and disposition

Explicit session selection, literal prefix matching inside the requested scope, one metadata/text snapshot and zero-based citations all fit the vault. Selecting an independently archived child by its own UUID also fits. A child can legitimately have no indexed human request. Keep that outcome distinct from a lookup miss and label a tool-only assistant entry by its stored role. The tasks have vertical CLI/MCP slices, size and parallel markers, dependencies and a verification step. [Vault workflow](../../../reference/vault.md) · [Scanner role policy](../../../../internal/vault/scanner.go#L203) · [Child archive decision](../../../adr/031-transcript-model-seam-and-multi-platform-vault.md) · [Task graph](tasks.md#dependency-graph)

**Disposition.** Retain the explicit latest-exchange feature. Before implementation, settle the historical guarantee and the meaning of links from ranked hits, specify cold read behavior and close the metadata redaction gap. The focused FTS5 probes establish current decoder, storage and retrieval behavior. The proposed brief itself has no runtime implementation to validate.

## Resolution after recheck

All seven findings held on the source recheck. The agreed first release shows the latest indexed exchange. The findings above refer to the original proposal at `6677d7b:docs/feat/wip/vault-session-brief/`. [Revised design](design.md) · [Implementation tasks](tasks.md)

| Original finding | Resolution for implementation |
| --- | --- |
| 1. Physical-line cutoff | The CLI and MCP reject a cutoff. Citations identify normalized message starts. The Claude snapshots and Codex legacy decoder cases passed on recheck. |
| 2. Ranked hit points at another turn | Both search surfaces identify a chunk start. The suggested action opens the session's latest exchange, including for a title-only main hit. Sidecars retain their identity and independently archived children use their own ID. |
| 3. Opening can initialize or recover | Read through a separate authenticated existing-file connection, including on an active MCP server. Apply the reader marker and compatibility checks inside the data snapshot. Missing files, valid empty vaults and authentication failures have distinct outcomes. The driver can report an ambiguous wrong-key-or-damage cause. |
| 4. Effective project can contain sensitive input | Both metadata and selected messages get complete-field redaction before escaping and clipping. A field above the input cap gets an explicit omission marker. A clipped or redacted ID cannot be advertised as a usable selector. |
| 5. Widened search needs the original scope | The follow-up instructs the caller to reuse the search's project arguments. An emitted cross-project hit must open through that instruction. A two-row ambiguity probe reports ambiguity without an exact total. |
| 6. A UUID can be replaced | Each call reads the current committed archive. Replacement, rename, changed scope and deletion have explicit next-call outcomes. A writer interleaving with one call cannot mix revisions within that brief. |
| 7. Unindexed selectors scale with the vault | The reader scans scoped positions once and fetches up to three bodies by rowid. The first task names an encrypted workload, a deadline and the decision to revisit the query if it misses that target. |

**Feasibility evidence.** A temporary Go test used the checkout's pinned SQLite driver, FTS5, a synthetic key and 1,000 session IDs with 100 rows each. Each row carried 256 bytes of text. An existing-file reader selected the first user, latest user and assistant (rowids 1, 99 and 100) from the oldest session. With 44,335,352 bytes of WAL still present, authenticated open and lookup took 240 ms. After writer close the database was 43,921,408 bytes. Three fresh connections took 236 ms each for open, lookup and close with the OS cache warm. A 1 ms caller deadline interrupted a scan. Opening a missing path left it absent. A wrong key produced the driver's authentication diagnostic.

The second pass distinguished stale per-session indexes from incompatible database layouts, specified how to omit a field too large to redact in full, and reconciled the search action with the compact writer's per-hit allowance. Focused FTS5 tests for label normalization, literal prefix matching, import/merge replacement and default/explicit MCP project scope passed.

The timings cover the storage operations on synthetic rows with a warm OS cache. The final end-to-end measurement, rendering, registration and public integration cases belong to implementation acceptance. [Verification workload](implementation.md#verification)
