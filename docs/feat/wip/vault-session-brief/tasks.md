- 2026-11-27 · superseded (see next entry) · Lookup keeps the existing pure literal-prefix semantics (`GetSession`, design §Interface). A legacy filename-derived ID that is a strict prefix of another in-scope ID therefore resolves as ambiguous even when passed in full, and no longer ID exists; `LIKE` also folds ASCII case, so IDs differing only by case collide the same way. A search hit for such a session still offers the brief action, which then dead-ends. Fixed-length lowercase UUIDs cannot hit this. Not changed here because preferring an exact match would deviate from "existing vault lookup semantics". Owner: unassigned · next action: decide whether an exact full-ID match should win for the brief (and `vault show`) · verify: a test with IDs `x…` and `x…-2` resolves the shorter one.
- 2026-11-27 · accepted (user decision in session, 2026-11-27) · A complete session ID now wins over prefix matches in every lookup path: `GetSession` (show/restore/resume), rename, project assignment, delete planning and the brief, via `preferExactSession` (store.go) and an exact-first scoped query in the brief resolver. Shorter prefixes keep their ambiguity; scope still applies before matching; delete's `ExactIDs` mode is unchanged. Rationale: the previous rule left such sessions unreachable by any input; the new risk needs the same rare legacy collision plus a user who meant the longer ID while typing the shorter one in full. Isolated review (internal APPROVE with two P3s; codex REQUEST_CHANGES with two P2s) led to: `GetSession` decoding only the selected transcript (a damaged candidate no longer blocks an exact match or an ambiguity report); an `ExactID` option on `RenameOptions`/`ProjectOptions`, set by the TUI, so a session deleted while its editor is open is reported missing instead of resolving to a longer ID it prefixes (this also lets the TUI rename IDs shorter than eight bytes); a TUI `getSession` helper that rejects a lookup returning a different ID, used by every TUI lookup (viewer, raw view, project editor, child launch), so a stale selection is never shown or edited as another session (codex rounds 2–4, inherited paths also present at `49ed7c1`); the TUI's startup `view` argument keeps prefix lookup (operator input); reindex skips a session whose enumerated ID now resolves to a different one (`rebuildSessionFTS`); TUI-deferred restore/resume resolve their captured ID exactly (`lookupVaultSession(..., exact)` in cmd/capy/vault.go) while command-line arguments keep prefix lookup; metadata-only `scanSessionMeta`; docs qualified to "of at least eight characters"; cross-referencing comments between `preferExactSession` and the brief resolver. Committed separately from Task 2. Verify: `internal/vault/exact_id_test.go`, TUI rename/project-edit/raw tests, `TestPerformTUIAction_StaleIDNeverActsOnAnotherSession`.
