### Invariants that bite

- **Verbatim bytes.** `raw_jsonl` is the plain (decompressed) file; `content_hash` and `size_bytes` are computed on those bytes (`computeContentHash`). Never hash or store `.zst` bytes.
- **`content_hash` is a framed digest, not `sha256(file)`.** `computeContentHash` writes `len(key)||key||len(content)||content` for every entry of a map keyed `<uuid>.jsonl` (plus sidecar paths) into one SHA-256. A restore round-trip test must compare **bytes** (or recompute `computeContentHash` over `{"<uuid>.jsonl": restored}`); `sha256.Sum256(restored) == content_hash` can never pass.
- **Three sites stamp the reader marker, not one.** `writeRecord`/`WriteBatch` (per write tx) and `compact.go` `markCompressed` (after recompression) both call `markMinReaderVersion`. When the function gains a version parameter, compact must pass `readerVersionZstd` (2) — passing the new `supportedReaderVersion` would lock older binaries out of a Claude-only vault the moment the user runs `compact`.
- **A new platform constant is a reader-version bump.** Every dispatch on `platform` is exhaustive over known constants, so a binary lacking a constant must refuse the vault at open. `ParsePlatform`'s table test lists the constants next to their `readerVersion*` and fails on an unpaired one. Consequence: an unrecognized stored value can only be corruption, which is why the `DetectFormat` sniff is safe (design § Format Identification).
- **`schemaSQL` runs before migrations.** `openDB` executes `schemaSQL` (store.go ~439) and only then `migrateVault` (~444). `schemaSQL` may therefore reference only columns that exist in every historical schema. New columns go into the fresh `CREATE TABLE` *and* an `ALTER TABLE` migration; a new **index over a new column goes into the migration only**.
- **Do not bump `currentIndexVersion`.** Claude extraction is byte-identical after this work; the version exists to detect stale Claude rows, and nothing here makes them stale (ADR-025). Codex rows stamp the current value.
- **Do bump the reader contract.** The first Codex row raises `vault_meta.min_reader_version` to 3 (design § Reader version). `markMinReaderVersion` is currently `INSERT OR IGNORE` and cannot raise an existing marker — it must become a monotonic upsert.
- **Migration pattern.** Copy `migrate0005AddSessionNames`: read-only fast path, `BeginImmediateContext`, re-check inside the transaction, `columnExists` guards, record by name.
- **Merge sources are not migrated.** `MergeFrom` opens the source read-only without running migrations, so every new column must be feature-detected (`columnExists`) and substituted with a literal when absent, exactly as `encoding` is today. An absent `platform` column means Claude — never sniff it.
- **Import decides against committed state only.** `Import` consults `SessionDigest` (DB) and batches writes in one transaction (`WriteBatch`), so two files for one uuid in one run collide on the primary key unless an in-run map is consulted first (design § Import).
- **Consumers own policy, decoders own format.** Secret stripping, truncation, `ftsExcludedResult`, collapse thresholds and labels live in scanner/render/transcript. Decoders never sanitize.
- **The viewer owns no store.** `tui/viewer.go` is fed by the root `Model` (`tui/app.go`), which owns `dataStore`, the context and `openSession`. Anything that needs a DB read is a root-routed action.
- **One rendered TUI row is one viewport line.** Any new marker row must pass through `singleLine` (see `docs/architecture.md` § Tool-result display).

### Slice 7: Codex discovery, import and restore round-trip

1. `internal/config/paths.go`: `CodexHome()` honoring `CODEX_HOME`, default `~/.codex`. → verify: unit test with the env set and unset.
2. `discovery.go`: introduce `Discoverer` with `claudeDiscoverer` (today's code) and `codexDiscoverer`; `parseRolloutFilename(name) (localTS, threadUUID, rolloutID string, compressed, ok bool)`; `SessionFile` gains `Platform`, `RelativePath` (slash-separated, `.zst` stripped), `ProjectPath`, `Compressed`, `OnDiskSize`.
