# Implement structured knowledge sections

## Markdown ingestion

Give knowledge indexing a block packer in `internal/store`. Keep the exported `SplitOversized` used by vault windows on its current partitioning. Inspect raw lines with one fence recognizer shared by Markdown detection, section boundaries and classification. Use a trimmed view only where the grammar permits it. For ATX headings accept 1–6 hashes after at most three spaces, followed by a space, tab or end of line. Strip a syntactic closing hash run from the title and keep the source heading line in the body. Keep the existing horizontal-rule boundary outside fences. [Current chunker](../../../../internal/store/chunk.go#L24) · [Detector](../../../../internal/store/detect.go) · [Vault caller](../../../../internal/vault/chunker.go#L108)

Record the fence state on line spans while scanning. Fill each new chunk with complete blocks first. For a block exceeding the whole budget, fill with complete lines before splitting a long line. This preserves a small fence after a large paragraph. Classify from the spans actually emitted, including the opener and closer. Normalize CRLF to LF consistently for this projection and preserve code indentation, empty lines and trailing spaces. Track complete eligible prose lines separately so overlap can use only the space left after packing new material. Apply the bounded fallback to empty, whitespace-only and rule-only input when the scan yields no blocks. A single heading-only auto-detection fixture needs another Markdown indicator or an explicit Markdown format.

## Titles shared by both formats

Finalize the titles of one source in emission order before it enters the write transaction. Build a bounded candidate from its heading path or JSON coordinates. Preserve meaningful leaf and identity text when shortening the path, allocating space to both when both are long. Normalize invalid UTF-8 and line/control characters in title components before fitting. Use deterministic prefix clipping on rune boundaries with an ellipsis. Reserve space for numeric row, field and part markers and any collision suffix first. Keep a set of final titles. If the candidate already occurred or ends in the reserved literal form ` [section N]` for positive decimal N, refit it with its own source ordinal as the final suffix. This keeps generated suffixes unique even in a manual that uses the same words. Apply this step to Markdown and successfully parsed JSON. Plaintext and malformed-JSON fallback retain their existing partitioning. [Fusion consumer](../../../../internal/retrieval/retrieval.go#L327)

Plain text and other admitted media keep their plaintext path. ## JSON ingestion

Decode the sanitized document with `json.Decoder.UseNumber`. Require one complete value and EOF after optional whitespace. Retain the existing Go decoder semantics for repeated input keys. A parse failure uses `chunkPlainText` on the complete sanitized input while the source retains its selected JSON format. A successful parse produces code chunks, including empty arrays/objects and explicit root scalars. Preserve the original sanitized-input hash for both outcomes. [Current dispatch](../../../../internal/store/index.go#L268) · [Current walker](../../../../internal/store/chunk.go#L282)

Use compact Go JSON encoding for the stored representation. Sort object members by their original decoded key, preserve array order and encode numbers directly from their lexical spelling. Redact complete decoded strings and keys, including array identity values, before encoding or clipping. Group from a list of members. When redaction gives distinct decoded keys the same spelling, mark that object and its ancestors for descent even if they fit. Flush before a repeated safe key enters a group. This keeps both values accessible in JSON objects with distinct member names. Recognize strings and `json.Number` in the existing identity preference order (`id`, `name`, `title`, `path`, `slug`, `key`, `label` when the first array element is an object). Use indices when a row has no usable identity. Fitting batches keep the existing short identity or index-range titles. [Identity selection](../../../../internal/store/chunk.go#L391)

1. Compute compact encoded sizes bottom-up from encoded keys and leaves. Saturate container sizes above the cap. Include separators, quotes and brackets/braces. A fitting value can then be written once into its final group. Grow each batch by its next item’s cost. Small named objects with nested containers outside array rows retain child paths. A flat fitting object or a fitting array row stays whole unless safe-key collisions require descent.
2. In an array, flush a full batch before handling an element on its own. An element that fits only without array brackets is emitted intact. For oversized arrays, apply the same rule recursively. For an oversized object, greedily group fitting members by their wrapped cost, preserving sorted order. An individually over-budget member flushes the group. Carry its key in the path and emit its value alone if it fits, otherwise descend into the value. Preserve the enclosing record identity on nested fields and include nested indices as needed.
3. For detached keys whose searchable spelling would be clipped out, write ordered key pieces at that member’s position. Assign such a field its one-based member ordinal in a source-wide depth-first traversal (sorted keys and array order). Reserve that same `field N` marker on key pieces and on the associated value pieces or first child group. This also distinguishes two detached sibling names sharing the same display prefix. For strings and numbers that still exceed the cap, reserve the two outer quotes and accumulate whole decoded runes by their actual JSON-escaped byte cost. Emit the largest fitting prefix and continue. This keeps escapes intact even at the byte boundary. Use one-based part numbers for `fields`, `key` and `value` titles. Short groups and fragments from one row share its identity.
4. Cache encoded leaf/key lengths and keep one push/pop path stack with a bounded title view. Avoid serializing whole subtrees at every ancestor, joining a long path for every descendant, or rebuilding an entire array prefix for each candidate. Use references to original components for full-key retention. Render only bounded prefix views for repeated ancestor and identity labels, including unusually long Markdown ancestors.
