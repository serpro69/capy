# Implement readable fetched pages

## Article selection

Extend the existing HTML conversion path in `internal/server/tool_fetch.go`. Reuse the existing parser/converter stack and table support. Normalize the response media type once (parameters and case included). On the parsed, inert tree, first eliminate hidden and boilerplate nodes, then select a content root, preserving visible title and code. Treat `hidden`, `aria-hidden="true"` and inline `display:none`/`visibility:hidden` as explicit visibility signals. Avoid a CSS engine. Bound traversal by the admitted body: the pinned parser already rejects nesting deeper than 512 elements, and the pruning walk is iterative. Decode the body first from its BOM, Content-Type charset or `<meta>` prescan (UTF-8 default) using `golang.org/x/net/html/charset` labels, failing on a declared unknown label and capping decoded bytes at `fetchMaxBody`. Redact `<private>` regions (any attributes, nested) on the token stream before parsing, because the parser can move a private region's content out of its wrapper; placeholders do not count as visible text. A self-closing `<private/>` opens a region. An unterminated region, a stray end tag, or a `private` element the parser still builds after the token pass fails conversion (`errPrivateBoundary`). After all pruning (including SVG `title`/`desc`/`metadata`/`defs`/`symbol`), coalesce text runs and apply `sanitize.StripSecrets` per text node and rendered attribute, because Markdown escaping hides token prefixes from the store's sanitizer. Never apply secret patterns to raw markup: the generic key=value pattern can consume an attribute's closing quote. Exempt `role="tabpanel"` from the `hidden` signal. Pass `markdown` as the content type for converted HTML. Previews use `sanitize.StripSecrets` of the converted Markdown, the same transformation the store applies after its size check. Send only the sanitized converted representation downstream for storage, comparison and previews. Propagate conversion/empty-body failures through both the single and batch paths before `IndexFetched` can renew freshness.

Step → verify a table and indented example under `main`, a hidden duplicate main, fallback to visible text outside an empty main, two sibling articles, a short valid page, and an empty application shell revalidated over a previously indexed manual. Check both returned preview and searchable content. On failure, other URLs in a batch can still succeed.

## Link origin and negotiation

Return the successful final response URL (`resp.Request.URL`) from `fetchRemoteContent`. Carry it, together with the configured `max_source_bytes`, through `fetchItemResult` to the serial conversion in batch and directly to conversion for a single fetch. Set `User-Agent` and the design's Accept list during request construction. The client copies both headers to each redirect. On the pruned tree of the selected root, resolve each `a[href]` against the final URL and ignore `<base>`. Keep a link when the result is http(s) without userinfo and the link has visible text. Otherwise, replace the link with its children. Replace each `img` with a text node containing its alt text. Redact each resolved destination with `sanitize.StripSecrets` as soon as it is produced, because a fragment inherits the final URL's query. Add the redacted length to a running total. When the total exceeds `max_source_bytes`, stop rewriting and return a source-size conversion error. Like other conversion failures, it occurs before `IndexFetched` and keeps the prior copy and validation time. The budget limits expansion while rewriting. The store's existing size check still decides admission for whatever renders. Keep the requested URL in `composeFetchCacheKey`. Reuse the existing transport, redirect, response-size and binary checks.

Step → verify a redirect across path bases in both single and batch mode. Use a relative reference, a fragment rendered as the absolute final URL, an image rendered only as alt text without a URL or data URI, and `javascript:` and credential-bearing destinations that render as text only, including credentials inherited from the final URL. Add a conflicting `<base>` element that conversion ignores. Assert the User-Agent and Accept headers on both requests, a request count with no embedded fetch, requested-URL deduplication and a cache hit on the second call. A test server that selects HTML or JSON from the Accept header returns HTML through the HTML path after a redirect. A server that offers only `application/vnd.example+json` is still indexed as JSON. With a small configured `max_source_bytes`, a link-heavy page fails for that item and keeps its prior content and validation time, and the next batch item succeeds.

## Verification

Use the existing in-process fetch fixtures and test transport. The acceptance fixture belongs to capy; the ignored upstream checkout is for comparison only. In the fixture, `main` contains a repository-style file table outside a sole article, and the article contains an API table with a known answer. A sidebar outside `main` would not test the selection rule. Single and batch previews start with the article. A source-scoped search finds the API-table answer and not the file listing. Keep a `main` without an article and a two-article page as controls. For admission, use a small `max_source_bytes`. A page that exceeds the limit only before redaction is admitted under the [ADR-022](../../../adr/022-source-size-guard-and-db-bloat-prevention.md) amendment. A page that still exceeds it after redaction fails and keeps its prior copy. Verify TTL, kind, validation time, a failed revalidation counted as one attempted miss, mixed-batch order, timestamp capture before the serial queue and existing fetch limits with synthetic keys. Run `make bench-quality` only as a regression check, because its cases do not exercise HTML article selection. Document output and failure examples in the tool reference.
