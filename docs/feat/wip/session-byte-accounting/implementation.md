# Implement session byte accounting

## Index and fetch replies

Keep the existing input measurement points. In `tool_index.go`, count inline `len(content)` after request and Read-policy checks, immediately before `Index`. Return its success or store error through `trackToolResponse` once. Read file and directory volumes from the outcome of `IndexPath`. Post a directory's total when the walk returns, including its partial result. Keep the single tracked directory summary. [Index handler](../../../../internal/server/tool_index.go) · [Directory aggregation](../../../../internal/knowledge/directory.go)

Add a submission flag to `knowledge.FileResult`. Set it alongside `BytesIndexed`, immediately before `indexContent`. A submitted file can be empty or the store can return a nil result with an error. An oversize probe can read bytes without ever reaching the store. Use the flag to track the file's final error after submission, including cancellation discovered on return. Keep pre-submission file failures untracked. The CLI and recursive walk can continue to use their existing byte totals. [File producer](../../../../internal/knowledge/index.go) · [Current limit and dedup fixture](../../../../internal/server/tool_index_bounded_test.go)

In `tool_fetch.go`, take the body's byte length after `fetchRemoteContent` accepts it and before `indexFetchedContent` converts it. In batch mode record each accepted item's length once in the serial phase. Compute the receipt's successful index-input size from the full string offered to `IndexFetched` on success, including unchanged revalidation. Use zero for a cache hit or failed submission. Preserve the body length across an error from conversion or the store. Share the two labels and units across fresh single receipts, single post-admission errors and aggregate batch receipts. Show both sizes as zero on a single cache hit. Keep previews, source identity, freshness, per-item success/failure and retry guidance intact. These changes work with either page converter and with a source ID in the receipt. [Fetch handler](../../../../internal/server/tool_fetch.go) · [Readable pages](../readable-fetched-pages/design.md) · [Source browsing](../knowledge-source-browsing/design.md)

For single-URL errors before a body is available, use the typed cache outcome to track the reply on an attempted miss. Preserve existing untracked argument, pre-dispatch cancellation and policy-error exits. A Git-platform advisory already returns a tracked reply with no cache outcome. Keep the existing per-item outcome recorder and one final response tracker per batch, even if every item fails. This keeps the tracked reply count per MCP call, cache outcomes per eligible URL, and admitted bytes per accepted body.

## Concurrent knowledge inventory

In `server.go`, replace the store pointer's `sync.Once` initialization with a mutex protecting that same pointer. Under the mutex, `getStore` reuses an existing handle or constructs a local one, installs its Read-policy checker, then publishes it. Give stats and shutdown an accessor that takes the same mutex and returns the current pointer, including nil. Release it before `ContentStore.Stats` or `Close`. The constructor builds a handle and the first store operation opens SQLite. A stats-only call on a fresh server must never invoke the creating accessor. Keep the workload snapshot lock out of all inventory I/O. [Server lifecycle](../../../../internal/server/server.go) · [Knowledge inventory](../../../../internal/store/cleanup.go) · [Report reader](../../../../internal/server/tool_stats.go)

## Workload totals

Split `SessionStats.BytesIndexed` into explicit knowledge submission and admitted HTTP body counters. Remove its legacy sandbox accumulator and `AddBytesSandboxed` along with their test-only uses. Keep the ingestion-layer `BytesIndexed` fields, which already measure raw submissions. `RecordRunCompletion` owns observed/captured bytes and completion counts. Status reads, the batch aggregate and storage inventories contribute no run input. Copy the counters, both response maps and the interval start together in `Snapshot`. Initialize the interval start and `SessionStart` from one clock sample. In `Reset`, set a fresh interval start and clear every counter and map under the mutex while preserving `SessionStart`. [Counter implementation](../../../../internal/server/stats.go) · [Owner callback](../../../../internal/server/tool_execute_run.go)

Render exact integer byte counts for each measured component, captured subset, workload total, per-tool rows, report overhead, estimated reduction and cache estimate. Keep existing human-size formatting for storage inventories. Compute the floored byte difference in integer arithmetic. Convert operands before multiplying by 100 for the percentage, then apply the 99.9% ceiling only for positive returned volume. A value such as `1 << 60` must work. Take the zero-input branch before division. Print the measurement start in UTC and keep uptime as server age. The examples specify the expected rendered values. [Design examples](design.md#workload-byte-reduction-estimate)

## Report overhead

In `handleStats`, partition `capy_stats` from the copied maps before summing workload calls and bytes. Show the workload components, totals and overhead on a cold report, an input-only snapshot and a report-only interval. Track the finished stats text exactly once after rendering. Use the existing conventions in `trackToolResponse`. For structured results, measure the length of the byte slice returned by a successful `json.Marshal(result)`. For a text-only result, sum the Go string byte lengths of its text blocks. Keep both scope and measurement conventions visible. Remove the old multiplier, token estimates, duplicate savings sentence and claims about what entered the model. [Response tracker](../../../../internal/server/tool_execute.go) · [Current report](../../../../internal/server/tool_stats.go)

The reset point is a successful non-dry-run `PurgeAll`, before the cleanup response and any optional reclamation. A later reclamation failure cannot undo that reset. Input updates, cache outcomes and completed reply measurements keep their individual posting times. No request-wide lock or reassignment to its start time is necessary. [Cleanup sequence](../../../../internal/server/tool_cleanup.go) · [Run reset rule](../../../reference/runs.md#storage-policy-and-diagnostics)

## Verification

| Acceptance case | Observable result |
| --- | --- |
| Index the same file twice, reject an oversize file before submission, and submit to a failing store | The first two submissions count in full. The pre-read rejection adds no input or counted reply. Each submitted file failure, including an empty file, counts the actual error text once. For a 128 B inline submission returning a 107 B error, the isolated report would show 21 B (16.4%) reduction. Assert using the actual error length. A partial directory posts its submitted bytes once and one summary. |
| Fetch HTML with a long comment and a short visible body, then hit its TTL cache | The first receipt and snapshot agree on admitted body bytes. Successful index-input bytes match the full representation sent to the store. The hit adds its reply and the chunk heuristic. Check single and batch receipts. |
| Fail a single fetch and a one-item batch after body admission | Each records one body, one attempted miss and one reply of its own actual size. The receipt shows zero successful index-input bytes. Exercise a store-size rejection and a conversion error. A small HTML body nesting 520 div elements reaches the pinned parser’s depth limit through both handlers. A transport miss contributes a counted reply and zero admitted bytes. A malformed top-level TTL is rejected before accounting. |
| Read reports on a cold server and between input and reply, then issue back-to-back reports | Totals and overhead remain visible at zero counted workload replies. The later report adds exactly the first report's text length to overhead. Compare the named workload fields, since inventories and uptime can change. Two 60 B rows sum visibly to 120 B. Check the design examples, equality, the 99.9% edge and cache-only activity. |
| Reset through `handleCleanup` while a yielded run is held before completion | A dry run keeps the interval. A real purge starts the next interval with its own measured cleanup reply. Release the run and observe its whole outcome once. Two `handleRuns` reads add two counted replies and their serialized byte lengths. Observed and captured totals stay at the completion values. Reuse the yielded file/batch tests. Also pass an incomplete outcome with known observed bytes greater than captured bytes to the observer and assert that only the observed total enters the denominator. [Owner tests](../../../../internal/server/run_diagnostics_test.go) |
| Call `handleStats` alongside the first `handleIndex` on a fresh server under `-race` | Both handlers complete, the optional inventory is safe and a later report sees the indexed source. A stats-only control leaves the knowledge handle nil and creates no run store. Also cover concurrent snapshot/reset and completion under the race detector. |

Use FTS5 and both synthetic keys. Compare text counts against the entire returned text, including Markdown and the batch footer. For structured run reads, compare the delta with the serialized result including fallback content. At implementation, update `toolStats` help, the README tool row, the architecture, and the tool and run references. Coordinate their description of zero input and the new denominator with the [ADR-013 reporting decision](../../../adr/013-configurable-fetch-ttl.md#workload-byte-reporting-decision-2026-11-23). Keep the existing captured-run and cache policy tests and update assertions tied to retired fields and labels.
