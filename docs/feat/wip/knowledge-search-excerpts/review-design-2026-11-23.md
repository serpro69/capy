## P1 — resolve before implementing the shared formatter

### 1. TECH_RISK — The winning FTS row can lose the only body match

The design promises a title-only fallback but leaves the formatter to distinguish it from a body match using a single highlight string. Both FTS layers supply a marked-up body, but fusion keeps just the row with the better individual BM25 score. The surviving string also has the same marker pair for every query term, synonym and stem. Stripping markers and comparing bytes establishes offset integrity. It establishes neither which query term a span represents nor whether the other layer had useful evidence. [Result contract and assumptions](design.md#result-contract) · [Layer query](../../../../internal/retrieval/retrieval.go#L170) · [Fusion](../../../../internal/retrieval/retrieval.go#L334)

I checked SQLite FTS5 with a chunk titled `migrating`, a 1,616-byte body ending in `tables migrated.`, and 30 other rows containing `migrated`. Porter marked the late word. Trigram returned the same row with no body marker and a better individual score (−0.592 versus approximately −0.000000292). A source filter can select only the target while both tables retain these corpus statistics. In a second case, an early `db database datastore` yielded three marked spans for one expanded query term. Counting distinct marked spellings would overvalue that passage. A display rescan after a redaction or control replacement also needs a fallback for a stem or fuzzy correction absent from the literal query. [Synonym groups](../../../../internal/retrieval/synonyms.go) · [Fuzzy pass](../../../../internal/retrieval/retrieval.go#L245)

Specify what counts as one original query term and what an unclassified span can establish. Preserve usable body evidence for the *same stored content* where available, or declare the degraded behavior and implement a safe fallback. Repeated titles mean evidence from a different body cannot be attached by source ID and title alone. Test a winning layer with no body markers, synonymous spellings in a distractor, and invalidated offsets with a late nonliteral match. Compare the resulting excerpt and keep ranking untouched. **Confidence 10/10** for the evidence loss, from the SQL probe and the fusion code.

### 2. INCOMPLETE — A returned mention can pass the test while the answer stays hidden

Consider a single Markdown chunk with “Call RetryBudget to set the limit”, over 1,500 bytes of neutral material, then a fitting fenced definition `func RetryBudget() int { return 3 }`. Both passages contain one distinct query term and one complete identifier with the same span. Source order picks the introduction. Preferring a whole fence *around the same match* does not settle this competition between two occurrences. An assertion that the late identifier appears can also pass against the introduction. [Scoring rule](design.md#result-contract) · [Proposed acceptance checks](implementation.md#selecting-and-displaying-a-passage) · [Task 2](tasks.md#task-2-show-the-strongest-passage-on-both-surfaces)

Choose the winner for this case. I recommend a fitting code block before source order for otherwise tied exact-symbol matches. Score evidence that can coexist in the final byte window, so a long paragraph cannot win on terms that the user will never see together. Test the distinctive answer (the signature and return value) in the actual CLI and MCP text. Include a prose-only control to keep ordinary prose searches useful. The existing quality suite evaluates needles in the full chunk and can remain green with either rendering. **Confidence 9/10** because the specified ordering yields the early mention, while the preferred tie-break is a product decision. [Capy benchmark](../../../../internal/store/bench_test.go#L322) · [Upstream answer checks](https://github.com/mksglu/context-mode/blob/0fe3f5da/e2e/cases/GP-SEARCH-heldout.e2e.mjs#L136)

### 3. INCONSISTENT — MCP has no source or title bounds to preserve

The contract says headers keep their own bounds. The CLI redacts and bounds source and title to 512 and 256 bytes before quoting. MCP interpolates both directly. Store indexing sanitizes the body and accepts the label separately. A long label or one containing a recognized secret can therefore dominate or expose data in a reply whose excerpt passes every proposed check. The sibling compact-replies design also touches metadata, but either feature is supposed to ship first. [Result contract](design.md#result-contract) · [CLI formatter](../../../../cmd/capy/search.go#L137) · [MCP formatter](../../../../internal/server/tool_search.go#L337) · [Indexing](../../../../internal/store/index.go#L63) · [Independent rollout promise](../knowledge-session-and-diagnostics.md)

Specify the per-field budgets and redact and neutralize controls before display clipping on both surfaces. Preserve the CLI’s quoting and define one-line MCP headers so an embedded newline cannot impersonate another hit. Test the first independently shipped feature with a long multibyte label and a synthetic credential in metadata. Whole-response accounting belongs to compact replies. **Confidence 10/10** from the two live formatters.

## P2 — settle these implementation boundaries

### 4. AMBIGUOUS — The NUL rule has more than one non-raw entry point

Task 1 covers the shared engine and `handleSearch`. Vault **per-line keyword** search has its own `autoQuoteFTS` tokenizer immediately beside the raw pass-through branch. Dedicated vault MCP and run search also have their own validators. A shared-engine-only change fixes chunk retrieval while the per-line Go API can still pass a NUL inside a quoted MATCH expression. The stated exception names raw vault syntax alone. [Keyword contract](design.md#result-contract) · [Per-line keyword and raw dispatch](../../../../internal/vault/store.go#L1525) · [Per-line tokenizer](../../../../internal/vault/store.go#L1813) · [Run validation](../../../../internal/runstore/search.go#L27)

Name the affected interfaces. Replace NUL with space before existing keyword rules on the intended paths, including per-line keywords if the broad contract stands. Define “separators” as NUL plus the existing whitespace rule if that is intended. Punctuation and stopword-only queries already have their own semantics. Check a mixed valid/blank batch before any shared-budget debit, an all-stopword control, NUL/space equivalence through the intended ordinary paths, and raw pass-through. Only `capy_search` owns the shared budget. **Confidence 9/10** because the independent tokenizer is confirmed and the intended scope is open. [Budget tests](../../../../internal/server/search_budget_test.go#L67) · [Raw-query consumers](../../../../internal/retrieval/retrieval.go#L228)

### 5. INCOMPLETE — “Whole fence” needs the same delimiter rules in either release order

A four-backtick tutorial may contain a three-backtick example. The current chunker toggles on either, and a historical chunk may start or end inside the block. The excerpt plan gives no closing rule or representation for a missing delimiter. An implementation can prematurely close the outer fence or display an invented closing delimiter as stored text. The sibling structured-sections design already specifies character, run length, indentation and trailing whitespace. [Excerpt contract](design.md#result-contract) · [Current fence decision](../../../adr/002-naive-code-fence-toggle.md) · [Sibling Markdown contract](../structured-knowledge-sections/design.md#markdown)

Reference that grammar in the excerpt contract and apply it to the available chunk independently of ingestion rollout. Where a real delimiter is missing, show contiguous available lines with a separate omission indicator. Exercise a nested shorter fence, a tilde fence and a historical partial block. **Confidence 9/10** because both parsers will see these inputs and only one design currently specifies their boundaries.

### 6. AMBIGUOUS — JSON fit and relevance can select different objects

An eligible array can contain a 1,700-byte object with an exact requested ID and a short neighbor that matches only a common key. “Best matching whole object if it fits” and “an oversized object receives a marked excerpt” leave room to return either. The separate tests for an oversized record and two similar records do not choose the winner in this mixed case. A record can also fit until the mandatory array-item label is charged. [Result contract](design.md#result-contract) · [JSON implementation](implementation.md#selecting-a-json-record) · [Task 3](tasks.md#task-3-show-a-fitting-json-record)

Rank records on match evidence first. Render the winning record whole if its stored slice **plus the label** fits, otherwise excerpt inside that record and mark the omission. Use the title-only fallback when no record has body evidence. Check the mixed-size case and the label-inclusive boundary, and assert a distinctive value from the winning record. **Confidence 9/10** because both readings change the visible answer on arrays that the current writer emits. [Current array writer](../../../../internal/store/chunk.go#L363)

### 7. TECH_RISK — The promised work bound lacks a measurable definition

Redacting an entire legacy candidate and finding its strongest late passage both require inspecting input proportional to its size. A forward scan can bound retained scoring state, while retaining a position or window for every repeated match defeats that aim. The current formatter does collect all positions. The 64 KiB ceiling only bounds the JSON decoder, and retained Markdown and JSON chunks can exceed the default 4 KiB chunk size. The CLI accepts up to 100 hits. [Passage implementation](implementation.md#selecting-and-displaying-a-passage) · [Current position collection](../../../../internal/server/snippet.go#L59) · [Retention contract](../../../reference/tools.md#cleanup-and-older-chunks) · [CLI limit](../../../../cmd/capy/search.go#L58)

State a bound for added scoring work in terms of chunk bytes and distinct query terms. Account separately for the full safe-text copy and bounded window state. A single repetitive legacy fixture with the best evidence near EOF can check the answer and allocation growth. Rank-quality benchmarks alone cannot measure this property. **Confidence 8/10** because the legacy input path is confirmed and the new allocation behavior depends on the implementation.

## Feasibility and verification

The data model already distinguishes source format (`s.content_type`) from chunk classification (`c.content_type`). The first belongs in knowledge-specific result metadata. The second is used by existing code/prose filtering and title boosting. The opaque result metadata can carry format alongside a future section coordinate. Selection within the winning chunk and redaction before slicing fit the existing storage contract. Returning a slice of *stored* JSON also avoids promising to restore original file serialization. [Knowledge row mapper](../../../../internal/store/search.go#L88) · [Result metadata](../../../../internal/retrieval/retrieval.go#L28) · [JSON writer](../../../../internal/store/chunk.go#L352)

The proposed task sizes, dependencies, parallel markers and verification order are coherent. NUL handling can ship independently. The existing vault-hit formatter and the separately bounded global-run knowledge response have their own presentation contracts. Reversing the formatter requires no data rollback. ## Resolution after recheck

**Design ready for implementation.** The recheck confirmed three defects in the original plan and five gaps in its contracts or verification. The decisions below close the design findings. The [task list](tasks.md) tracks implementation and runtime acceptance separately.

| Finding | Rechecked evidence and resolution |
| --- | --- |
| 1. Lost body highlight | Repeated the synthetic probe with the source filter, capy’s Porter/trigram schema and default BM25 weights. Trigram won (−0.59192) with no body mark. Porter marked the late stem. The reranker reads the winner’s original highlight. The plan retains separate, same-body evidence for display across fusion and fuzzy merging. [Evidence and fallback rules](implementation.md#match-evidence) |
| 2. Early identifier mention | The two occurrences tie under the original rule. A complete fence with the exact identifier now wins that tie. The fixture must put the definition beyond the first 1,500 bytes and show the signature and return value on both surfaces. [Passage contract](design.md#choosing-a-passage) |
| 3. Header bounds | CLI clips before quoting and MCP currently interpolates both fields. The plan preserves CLI behavior and bounds the finished single-line MCP label and title, including escaping. The contract works in either release order with compact replies or source browsing. [Safe fields](implementation.md#safe-fields) |
| 4. NUL scope | The separate per-line tokenizer and raw vault dispatch are confirmed. The plan names the behavior of each entry point, including stored run queries. Shared-budget rejection applies at federated keyword admission. [Input paths](implementation.md#keyword-normalization) |
| 5. Fence boundaries | Historical chunks can contain a shorter inner delimiter or only part of a block. The renderer uses the sibling fence grammar, real delimiters only, and whole available lines within the marked budget. [Markdown contract](design.md#markdown-and-json) |
| 6. JSON record selection | The current writer can store both a large and a small object in one array. Relevance selects the record first. Its chunk-local label and available bytes then determine whole or partial display. [JSON selection](implementation.md#selecting-a-json-record) |
| 7. Work bound | The existing collector accumulates every occurrence. The new bound covers selection workspace separately from full-field sanitization and fetched highlights. A repetitive late-match fixture checks the answer and allocation scaling. [Windows and cost](implementation.md#windows-and-cost) |
| 8. Prefix documentation | The live architecture guide still promises a prefix. Its update now appears alongside CLI help and the tool reference in the release task. [Task 4](tasks.md#task-4-verify-and-document-the-feature) |

The second read also aligned JSON span coordinates with the containing chunk, preserved the winning row’s identity for browse positions and compact references, and distinguished validated title-only evidence from unusable offsets. Unsafe offsets fall back to safe literal/synonym matching. A stem or typo with no recoverable safe spelling gets opening context. Local SQL evidence establishes the baseline behavior. The proposed Go integration cases and scorer measurements remain implementation checks.
