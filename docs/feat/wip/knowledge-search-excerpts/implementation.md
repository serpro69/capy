Apply it at `SearchWithFallback` entry so synonym-AND, flat-OR, vocabulary correction, proximity and entity boosts all see the same text. Use it in the public Porter/trigram query builders and for the raw rerank text of a direct `RRFSearch` call. That lower-level call still accepts prepared FTS expressions for its two layer arguments. The helper replaces only NUL. [Keyword builders](../../../../internal/retrieval/query.go) · [Retrieval flow](../../../../internal/retrieval/retrieval.go#L228)

## Selecting and displaying a passage

Replace the window collector in `internal/server/snippet.go` with one knowledge excerpt selector usable by `formatKnowledgeHit` and CLI `writeKnowledgeSearch`. Give it the normalized query, stored body, source format and available display highlights. Return the rendered text and the selected half-open byte span relative to the **whole display-safe chunk**, including for an inner slice of a JSON object. This span covers source text only. A compact-reply caller may use it as an original span when the representations agree, or emit a full hit if location is ambiguous. A browse position always belongs to the winning table and row. The standalone formatter needs no new browse coordinate. [Existing MCP formatter](../../../../internal/server/tool_search.go#L337) · [CLI formatter](../../../../cmd/capy/search.go#L132) · [Compact reply identity](../compact-search-replies/implementation.md)

### Safe fields

Run `sanitize.StripSecrets` on complete fields before any slicing, even for fitting bodies. Repair invalid UTF-8, then apply the control rules in the design. Retain CLI `%q` and writer-error propagation. For MCP, render line breaks (including Unicode line and paragraph separators) and tabs visibly on one line. Clip at a rune/escape boundary, charging escaping, any quotes and the omission marker to the field. Reuse the ranked-header helper if source browsing or compact replies lands first. Pass the finished excerpt to any enclosing reply writer exactly once.

### Match evidence

Reuse the retrieval term filter, including its stopword fallback. Group synonymous query spellings using `ExpandSynonyms` and credit each group once. Preserve original case separately for complete identifier matches in camel/Pascal case, underscore and dotted names. Match those identifiers case-sensitively at the boundaries of the complete name. A substring of a longer identifier earns no whole-identifier credit. For case-insensitive comparisons, track offsets in the safe UTF-8 text as runes are visited. [Term filter](../../../../internal/retrieval/query.go#L14) · [Synonyms](../../../../internal/retrieval/synonyms.go)

For the two knowledge display callers, opt in to retaining display-only highlights during retrieval. After the existing fusion winner is known, take at most one marked string per participating layer from its fusion bucket with byte-identical content. Keep the winning row's main `Highlighted` field, BM25 score, fused score and `Meta` intact. Reranking consumes that main field. On a fuzzy merge, keep the current primary winner and supplement only from the same body, retaining at most the two layers from each of the original and corrected passes. Never merge offsets across different content sharing a title. Use strings already returned by the query, without a second database read. Vault and run callers use their current result path. [Fusion and fuzzy merge](../../../../internal/retrieval/retrieval.go#L327) · [Reranker](../../../../internal/retrieval/rerank.go#L57)

Validate each available stream before use, including the winner's unmarked body when supplied. Require paired, unnested STX/ETX delimiters on rune boundaries, no literal marker bytes in the stored body, and exact reconstruction of that body on stripping markers. Use offsets only when the safe body also equals the stored body.

- With valid body marks, associate visible query spellings or synonyms with the marked ranges. An exact identifier can span multiple marked tokens. Count an unexplained mark once per candidate as location evidence, including when both layers mark it. An explained mark supplies no extra credit.
- If every supplied stream is valid and none has a body mark, take the opening fallback. An incidental substring in the body cannot override a confirmed title-only result.
- If no usable body mark survives and any stream failed validation, or none was supplied, scan the safe body for case-insensitive literal groups and synonyms. When only an unmappable stem or correction matched, take the opening fallback. Emit bytes exclusively from the safe body.

### Windows and cost

Reserve the actual edge indicators (`…\n` and `\n…`, four bytes each) before fitting or scoring a slice. Treat blank-line-separated prose and fenced blocks as units. Consider contiguous fitting units with their intervening whitespace. For an oversized unit, consider fitting runs of whole lines, or a sliding rune-aligned byte window within an individually oversized line. Score each finished candidate, including neighboring context, by the design's tie-breaks. A fence earns the tie-break only when both delimiters and the complete matched identifier inside it are visible. On an equal score at the same start offset keep the wider fitting context. A fitting full body bypasses selection. Opening context uses the same byte limits.

Scan through the last byte with a rolling window of offsets, group counts and the best span. For a fixed query and budget, scoring work must grow at most linearly with body and marker bytes. Working storage for the scorer may depend on query size, group count and the 1,500-byte window. It must stay independent of the total number of occurrences or lines. Account separately for full safe-text preparation and the bounded number of already fetched highlight strings. Avoid materializing all tokens, positions or windows for an entire legacy hit. Measure scorer allocations separately from whole-field sanitization on increasing repetitive inputs with a late answer. [Existing window collection](../../../../internal/server/snippet.go#L59)

## Selecting a JSON record

Select `s.content_type` alongside `c.content_type` in the knowledge corpus on both layers. Put the source format in knowledge-specific result metadata, alongside any winning-row coordinates already used by compact replies or source browsing. Chunk classification still drives filtering and title boosting. Use stored source format `json` for eligibility. A plaintext or Markdown chunk can legitimately contain an array example. [Knowledge mapper](../../../../internal/store/search.go#L82) · [Current batch encoding](../../../../internal/store/chunk.go#L352)

After the full-body shortcut and the 64 KiB checks, parse exactly one complete array. Decode each top-level element as `json.RawMessage` and use its length and the decoder's end offset to locate its slice. Require every element to be an object and only whitespace before EOF after the array.

Score key and value spellings as indexed across each **whole object**, including its nested values. Use group coverage, exact identifiers, additional unassigned evidence, compactness and array order. Markdown fence preference applies only to passages. Keep the winning span and ordinal provisionally until the parse succeeds. Preserve escapes, number spelling and whitespace by slicing the safe bytes. If the winner exceeds the label-inclusive allowance, charge the label, newline and any omitted object edges before choosing the inner window. Malformed or ineligible chunks use ordinary passage selection. An eligible array with zero body evidence uses unlabeled opening context.
