## P1 — resolve before implementation

### 1. TECH_RISK — Public spawn code 127 cannot identify an interpreter lookup miss

The plan adds a doctor pointer to every newly constructed `runtime_unavailable` message. A preparation miss takes that path, but both supported supervisors also emit 127 when starting a phase returns a file-not-found error. On Linux I obtained the **same CLI exit, public code and message** for an absent Ruby executable and a selected Ruby shim whose shebang interpreter was missing. Fresh doctor counted Ruby in the second case. An existing Rust test goes further: the compiler starts, produces captured output and exits successfully, then its missing output binary causes `runtime_unavailable`. The helper discards the private error text, so adding candidate names in `prepare` only helps a direct executor caller. [Implementation plan](implementation.md#execution-error) · [Preparation mapping](../../../../internal/executor/stream.go#L92) · [Linux spawn](../../../../internal/executor/supervised_linux.go#L71) · [Darwin spawn](../../../../internal/executor/supervised_darwin.go#L109) · [Public mapping](../../../../internal/runstore/runs.go#L448) · [Supervisor handoff](../../../../internal/execution/supervisor_unix.go#L83)

Use public wording that allows for a missing executable or interpreter during startup. Offer doctor as a way to inspect PATH candidates. Preserve the error code, cleanup evidence and existing result snapshots. Verify both a genuine lookup miss and a discovered runtime whose launch fails, including the actual text the caller receives. This needs no new protocol field. **Confidence 10/10** from the two CLI cases and the existing Linux and Darwin compiler fixtures. [Linux fixture](../../../../internal/execution/stored_recovery_integration_test.go#L540) · [Darwin fixture](../../../../internal/execution/captured_darwin_integration_test.go#L305)

### 2. INCOMPLETE — The error points MCP operators only to terminal doctor

The design correctly distinguishes cached and fresh samples. Its only prescribed action in a captured error is `capy doctor`. A terminal can inherit a different PATH from the agent launcher. Even with **identical PATH strings**, I started MCP with empty directories, added executable shims to them, then saw fresh CLI doctor report Python, MCP doctor still report zero, and `capy_execute` successfully invoke `python3`. Both execute tool descriptions draw on the startup map. Their language enums and public admission still accept all eleven languages, and each captured run gets a fresh executor. [Operator contract](design.md#operator-contract) · [Error hint](implementation.md#execution-error) · [Tool registration](../../../../internal/server/tools.go#L14) · [Admission](../../../../internal/server/tool_execute_run.go#L61) · [Helper executor](../../../../internal/execution/stored_run.go#L68)

Name both entry points in the shared hint. Explain that `capy_doctor` explains the running server’s advertised inventory, `capy doctor` samples its terminal environment, and a failed run records its own outcome. If the launcher’s PATH needs editing, restart the server from the corrected environment. Keep an MCP connection alive across the install and check its inventory alongside an actual captured call. **Confidence 10/10** from the live stdio comparison and capy’s existing troubleshooting guidance. [Live-server acceptance task](tasks.md#task-1-show-selected-and-missing-runtimes-in-doctor) · [Operator guidance](../../../../README.md#L409)

## P2 — clarify the output and its verification

### 3. INCONSISTENT — Informational rows conflict with the tested checklist format

The plan asks for eleven detail rows under one aggregate check. The formatter currently emits one checklist line per check. `TestDoctor_ChecklistFormat` requires a pass, warning or failure marker at the start of every nonempty, nonheading line. Ordinary indented details fail that test. Giving each missing language a warning marker changes the operator contract. Specify one marked aggregate plus a defined continuation format. Update the format assertion to recognize those continuations only under the runtime check, retain strict checks elsewhere, and compare the runtime section across CLI and MCP even at zero detections. **Confidence 10/10** from the renderer and the existing assertion. [Output plan](implementation.md#cli-and-mcp-diagnosis) · [Formatter](../../../../internal/platform/doctor.go#L470) · [Checklist test](../../../../internal/server/tool_utility_test.go#L535)

### 4. AMBIGUOUS — Define what a missing row can truthfully say

“Controlled diagnostic categories” leaves open whether a row distinguishes an absent file from a permissions problem. The proposed input carries candidate names and the selected basename. The Go detector drops unsuccessful `LookPath` errors. A missing file, non-executable file and unusable symlink can therefore produce the same row. Upstream’s unreadable-candidate warning required its own per-path observations. Limit the rows to *selected* and *no candidate selected*. List the registered names in candidate order and suggest an executable in an absolute PATH directory visible to capy. Go’s default lookup can also decline a match reached through a relative PATH entry (`exec.ErrDot`). Include an unusable first entry followed by a usable one in the controlled PATH check. This preserves existing lookup rules and gives the operator accurate guidance without a second filesystem scan. **Confidence 9/10** because the data available to the renderer is explicit and the intended categories are unnamed. [Operator contract](design.md#operator-contract) · [Proposed input](implementation.md#cli-and-mcp-diagnosis) · [Detector](../../../../internal/executor/runtime.go#L39)

### 5. INCOMPLETE — The existing shim fixtures bypass discovery

The Rust and Elixir executor fixtures put a regular wrapper path directly into the cached map. They can pass if a future detector resolves the symlink target and loses the name its dispatcher expects. Specify a symlinked candidate pointing to a differently named dispatcher. Doctor should show the candidate basename and leave an invocation marker untouched. A separate captured call should reach the dispatcher under that basename. Putting `python` in an earlier PATH directory and `python3` in a later one also protects capy’s name-first ordering against an accidental port of upstream’s directory-first ordering. **Confidence 10/10** from both fixtures and the controlled run, which selected the later `python3`. [Verification plan](implementation.md#execution-error) · [Rust fixture](../../../../internal/executor/cwd_test.go#L115) · [Elixir fixture](../../../../internal/executor/cwd_override_test.go#L115) · [Upstream resolver](https://github.com/mksglu/context-mode/blob/0fe3f5da/src/core/sandbox/runtimes.ts#L101)

### 6. MISSING — A passing inventory can still leave every shell batch unavailable

The required aggregate counts **languages**. With Python and Ruby discoverable and no shell, CLI doctor reported a pass at `2/11`. The default CLI execute language is shell, and every batch child is stored with language `shell`. Keep the specified severity. Make the missing shell row or its operator example explain that these two workflows require `bash` or `sh`. An operator seeing a green summary can then identify the repair for a failing batch. **Confidence 9/10** from the observed pass and the fixed batch language. [Operator contract](design.md#operator-contract) · [CLI default](../../../../cmd/capy/execute.go#L95) · [Batch admission](../../../../internal/runstore/batch.go#L163)

## Feasibility and verification

The installer, hook routing, run schema and helper protocol can all retain their current behavior. The executor already owns the ordered names for all eleven languages, both doctors already share the aggregate formatter, and the real shim exercise confirms that execution through the selected spelling works today. A read-only presentation view over the registry and cached selection is sufficient. Keep the existing available-only map for execution and tool registration. The design’s exclusions, task sizes and dependency graph are proportionate to that change. [Executor registry](../../../../internal/executor/runtime.go#L8) · [Cached selection](../../../../internal/executor/executor.go#L49) · [Shared aggregate](../../../../internal/platform/doctor.go#L61)

I ran four existing checks on Linux with CGO, `fts5,integration` and synthetic keys. The zero/one/many aggregate, checklist format, bounded MCP spawn/compiler failures and stored Rust second-phase failure all passed. The separate stdio/CLI exercise used a binary built from this checkout and isolated temporary run storage. Its first assertion expected raw shim text, while the preview included the normal `[stdout]` label. The corrected assertion passed, along with the missing-shebang comparison. Darwin evidence comes from source and its integration fixture. These checks establish baseline behavior. The proposed rows and wording still need implementation acceptance tests.

## Resolution after recheck

All seven findings were confirmed against the current implementation and addressed in the design, implementation plan and tasks.

| Findings | Resolution |
| --- | --- |
| 1 and 2 — startup failures and process scope | The shared public message describes a phase startup failure and names both doctors. The operator contract distinguishes terminal discovery, the advertised MCP snapshot and the supervisor’s lookup. Private preparation errors retain the candidate names. [Execution errors](design.md#execution-errors) · [Error implementation](implementation.md#execution-error) |
| 3, 4 and 6 — doctor output | One marked aggregate owns eleven informational bullets. Each reports a selected basename or the ordered candidate names when lookup selects none. The missing-shell bullet identifies the default CLI and batch dependency even when the aggregate passes. [Operator contract](design.md#operator-contract) |
| 5 — shim behavior | One controlled fixture exercises real lookup, its preference across PATH directories, invocation through the symlink name and a live MCP snapshot across installation. [Verification cases](implementation.md#verification) |

The second read also distinguished a child’s own exit 127 from a phase startup failure, preserved pre-admission language validation and bounded historical results, and checked the shared proposal index for conflicting promises. Five existing Linux baseline checks passed across the platform, server, CLI and execution packages, including CLI exit classification and the Rust phase failure. The native Darwin case was checked in source. The design is ready for implementation. Feature acceptance and the before/after benchmark comparison belong to the pending tasks.
