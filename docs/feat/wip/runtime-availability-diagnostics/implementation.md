## Execution error

In `prepare`, include the registered candidate names when a supported language misses and keep `errors.Is(err, ErrRuntimeUnavailable)`. Unknown language values have no registered candidates. Both public entry points already validate the supported language set before admission. Keep that validation independent of the server’s available-only map. [Preparation](../../../../internal/executor/prepare.go) · [CLI validation](../../../../cmd/capy/execute.go#L40) · [MCP validation](../../../../internal/server/tool_execute_run.go#L65)

Keep the private error at the supervisor boundary. A preparation miss and a file-not-found error from starting a phase both map to spawn code 127. Change the fixed text only in the existing `runtime_unavailable` branch of `runstore.ApplyOutcome`. Suitable wording is “An execution phase could not start. Check PATH candidates with capy_doctor (server) or capy doctor (terminal).” This branch has no evidence identifying a missing candidate. CLI and MCP already use the stored message in their output and apply their ordinary response budgets. Preserve the error code, CLI exit mapping, run ID, capture and cleanup facts. Previously stored messages require no migration or read-time substitution.
